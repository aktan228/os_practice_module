Дополнительно сравнены **64 полных расписания**: set1/jobs/mixed/starve × 16 вариантов (FCFS, SJF, SRTF, Priority без старения, Priority aging=2 и aging=3, RR q=1…10). Все 64 совпали. Повторно прошли 13 собственных тестов, включая 420 симуляций на случайных наборах.

### Ограничения внешнего источника

В [sched.py](https://github.com/aktan228/operation_system_practice_tasks/blob/07f7b4bf1721ca904d997848e9c2a885a70abfcf/pr5/sched.py#L149) в строке 149 находится постороннее `alidate` перед ключом `turnaround`; полный файл не проходит синтаксический разбор. Снимок сохранён без исправлений. Для дифференциальной проверки загружается только просмотренная неизменённая часть исходника до определения metrics: импорты, Process, validate и simulate. Полный внешний CLI и его комплект тестов не объявляются успешно запущенными. Пять опубликованных результатов сверены отдельно.

README ПР-5 сообщает, что числа FCFS 9,25/15,75 из исходного условия ошибочны. Для данных set1 ручной расчёт, наш код и опубликованное расписание дают **8,75/15,25**. Оригинал преподавательского условия в просмотренном репозитории отсутствует, поэтому установлено совпадение с опубликованной ПР-5, а не выполнена независимая проверка недоступного первоисточника.

**Фото ручной диаграммы пока отсутствует.** Этот пункт не закрывается внешней сверкой. Образец FCFS и таблица ручного расчёта есть в README проекта 1. Фото сохранить как `project1/assets/fcfs_jobs_handwritten.jpg`, затем пересоздать README.

Данные банкира нельзя заменять числами из ПР-8: в проекте Available=[4,2,1] или [4,1,1], тогда как пример ПР-8 использует [3,3,2] или [0,1,0]. В проекте запросы проверяются каждый относительно исходного bank_state.txt; формат матриц отличается от JSON в ПР-8.

Для проекта 3 локальный формат строки — дата, время, IP, HTTP-метод, путь, статус, длительность в ms. Скрипт ПР-2 рассчитан на уровни ERROR/WARN и модули: его сохранённые числа и результаты strace не являются результатами проекта 3.

Пример продажи билетов содержит разрыв между поиском свободного места и его занятием. ПР-6 даёт подходы к синхронизации, но результаты экспериментов с буферами не подтверждают исправление этой программы. Во время этой проверки исправления и эксперименты для проектов 2–4 не выполнялись.

На фотографиях задания предоставлены блоки А, Б, В только для проекта 1. Полные критерии блоков для проектов 2–4 пока не представлены, поэтому их выполнение не заявляется по сходству тем с практическими работами.

## Воспроизведение сверки

Из `os_module/project1`:

```powershell
python verify_pr5.py
python -m unittest -v test_scheduler
python run.py
```

На Ubuntu/WSL: `python3` вместо `python`. Сеть не нужна. Результаты: `results/pr5_verification.json`, `results/pr5_published_checks.csv`, `results/pr5_differential_checks.csv`. При несовпадении опубликованного расписания, отдельной метрики или SHA исходника проверка завершается ошибкой.

# Модуль ОС: проект 1, практики А, Б и В

Для проекта «Планировщик учебного сервера» реализованы FCFS, SJF, RR, SRTF, вытесняющий Priority со старением и без него, а также трёхуровневый MLFQ. Исходные четыре набора данных сохранены. Материалы остальных проектов не изменялись.

**Полный материал для презентации:** [описание практик, команды, фактические результаты, таблицы и выводы](project1/README.md).

**Оформленный автономный отчёт:** [открыть HTML с диаграммами и таблицами](project1/results/report.html). SVG для слайдов и CSV для таблиц находятся в `project1/results`.

## Запуск

Из этой папки в PowerShell:

```powershell
python run_all.py
```

На Ubuntu из этой же папки:

```bash
python3 run_all.py
```

На Windows можно также дважды нажать `run_windows.bat`. Полные выводы команд сохраняются в `logs`, а последние выводы — в `run_output.txt`, `tests_output.txt` и `pr5_check_output.txt`. Сводка фактических проверок — [CHECK_STATUS.md](CHECK_STATUS.md).

На Ubuntu/WSL используйте `python3` вместо `python`. Требуется Python 3.11 или новее, сторонние пакеты не нужны. Одна команда пересоздаёт отчёт, README проекта 1, запускает 13 тестов и сверку ПР-5; сторонние пакеты не устанавливаются.

## Ключевые фактические результаты

На `jobs.txt` из трёх базовых алгоритмов SJF даёт минимальные средние ожидание **5,17** и оборот **9,00**. FCFS: **7,50 / 11,33**; RR q=2: **8,33 / 12,17**. У RR лучше первый отклик: **3,17** против **5,17** у SJF.

На `mixed.txt`:

| Алгоритм | Среднее ожидание | Средний оборот | Средний отклик | Переключения |
| --- | --- | --- | --- | --- |
| FCFS | 93,28 | 102,00 | 93,28 | 17 |
| SJF | 32,67 | 41,39 | 32,67 | 17 |
| RR q=2 | 30,83 | 39,56 | 8,61 | 76 |
| SRTF | 12,28 | 21,00 | 6,33 | 23 |
| Priority | 13,00 | 21,72 | 10,83 | 24 |
| MLFQ 2/4/8, boost=20 | 24,89 | 33,61 | 3,50 | 62 |

Для RR q=1 отклик равен **4,39**, переключений **145**; q=2 уменьшает их число до **76** (на **47,6%**), но отклик возрастает до **8,61**. Это компромисс: стоимость переключений в модели равна нулю, реальный оптимум по этой модели не доказывается.

На `starve.txt` процесс P1 без старения стартует в момент **57**, завершается в **63**. При старении каждые 3 единицы времени стартует в **21**, завершается в **27**: на **36** единиц раньше. Поток конечный; показан механизм голодания, а не бесконечное ожидание.

Вывод: при заранее известных длительностях SRTF выигрывает по ожиданию и обороту на смешанном наборе; при неизвестных длительностях разумен MLFQ с периодическим boost. На проверенном наборе все длинные задачи завершаются.

## Проверка и оставшиеся материалы

Прошли 13 тестов, в том числе проверка 420 симуляций на случайных наборах. Проверены согласованность CSV с временными диаграммами, XML всех SVG, ссылки на изображения и контрольные суммы входных файлов.

**Сверка с ПР-5 из указанного репозитория выполнена:** совпали 5/5 опубликованных результатов и 64/64 расписания на четырёх исходных наборах. Учтены RR q=3 в ПР-5 против q=2 в проекте и разные приоритеты set1. Подробности: [отчёт о сверке и статус проектов 2–4](REPOSITORY_CHECK.md), [полный раздел А3](project1/README.md).

В проверенном `sched.py` репозитория есть синтаксическая ошибка в строке 149. Полный скрипт не объявляется успешно запущенным: проверены сохранённые результаты и неизменённая часть с алгоритмами до функции metrics. Снимок 9 файлов зафиксирован по commit и Git blob SHA в `project1/reference/SOURCE.json`; повторная проверка работает без сети.

Осталось приложить **собственное фото диаграммы FCFS, нарисованной на бумаге**. Электронный образец и ручной расчёт готовы. Оригинал преподавательского условия отдельно недоступен: подтверждена сверка с опубликованной работой по предоставленной ссылке, а не с оригиналом задания.
